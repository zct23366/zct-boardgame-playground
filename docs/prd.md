# 需求文档

## 1. 应用概述

### 1.1 应用名称
昼夜繁荣桌游开发与试玩平台

### 1.2 应用描述
基于网页的桌游开发与试玩平台，为《昼夜繁荣》及类似策略桌游提供地图编辑、规则配置、游戏运行模拟、日志回放和数据分析功能。平台采用数据驱动架构，所有游戏元素通过JSON配置定义。

### 1.3 项目背景
《昼夜繁荣》是一款以「昼夜切换」机制为核心的中轻度策略桌游。本平台旨在为开发者提供完整的桌游设计、测试、调试工具链。

## 2. 用户与使用场景

### 2.1 目标用户
- 桌游设计者：设计地图、规则、事件
- 测试人员：运行游戏、验证规则、分析数据
- 玩家：试玩游戏、体验机制

### 2.2 核心使用场景
- 场景1：设计者创建新地图，配置格子属性和建筑规则，导出配置文件
- 场景2：测试人员导入地图和规则，启动游戏运行，观察昼夜切换和资源流转
- 场景3：开发者通过日志回放功能复现游戏过程，分析平衡性问题
- 场景4：使用数据分析模块统计格子访问频率、资源获取分布，生成图表

### 3.2 项目管理页

#### 3.2.1 项目列表
- 展示所有已创建项目，包含项目名称、创建时间、最后修改时间
- 支持点击项目进入编辑
- 支持删除项目

#### 3.2.2 项目创建/导入
- 创建新项目：输入项目名称，自动生成空白地图和默认规则
- 导入项目：上传完整项目配置JSON文件，解析并加载
- 内置项目模板：提供示例地图和规则供快速开始

### 3.3 地图编辑器页

#### 3.3.1 地图列表区
- 展示当前项目下所有地图，包含地图名称、创建时间
- 支持点击地图切换到该地图编辑
- 支持新建地图、删除地图、重命名地图
- 支持地图之间的格子模板共享

#### 3.3.2 地图网格画布区
- 以方块网格形式呈现地图编辑区域，每个方块代表一个格子
- 支持调整地图尺寸（行列数）
- 点击空白网格位置添加新格子（方块）
- 右键点击格子或使用工具栏删除格子
- 拖拽格子可重新排列位置
- 点击格子进入配置面板
- 方块以矩阵布局排列，可自由摆放

#### 3.3.3 格子配置面板
- 配置格子属性：
  + 名称（name）
  + 颜色（color）
  + 图标（icon）
  + 昼间类型（dayType）：Forest、Mine、Market、Empty等
  + 夜间类型（nightType）
  + 可否被替换（replaceable）：布尔值
  + 可替换类型列表（replaceList）：数组
  + 可否停留（canStop）：布尔值
  + 可否建造（canBuild）：布尔值
  + 是否有事件（hasEvent）：布尔值
  + 夜间收费（chargesAtNight）：布尔值

#### 3.3.4 地图导入/导出
- 导出地图配置为JSON格式文件
- 导入已有地图JSON文件，加载到编辑器

### 3.4 规则编辑器页

#### 3.4.1 格子模板编辑
- 定义格子类型（Forest、Mine、Market、Empty等）
- 配置格子属性模板，供地图编辑器使用

#### 3.4.2 建筑模板编辑
- 定义建筑类型：Camp、Village、City等
- 配置建筑属性：
  + 建设成本（cost）：wood、stone、rice数量
  + 昼间效果（effectDay）
  + 夜间效果（effectNight）
  + 过路费配置（canCollect）

#### 3.4.3 事件模板编辑
- 定义事件ID和名称
- 配置事件触发器（trigger）：enterTile、nightStart、phaseChange、sameTile等
- 配置触发条件（condition）
- 配置动作列表（actions）：addResource、stealResource、taxCollect、replaceTile、diceBattle等

#### 3.4.4 触发器规则编辑
- 可视化编写触发器-条件-动作规则
- 支持规则导出/导入JSON格式

### 3.5 游戏运行页

#### 3.5.1 顶栏
- 显示当前轮次（currentRound）
- 显示当前玩家（currentPlayer）
- 显示昼/夜标识（phase：Day/Night）
- 保存按钮：保存当前游戏状态为SaveFile JSON

#### 3.5.2 左侧工具栏
- 项目列表：切换当前项目

- 规则列表：选择使用的规则集

- 事件列表：查看所有事件定义
- 建筑列表：查看所有建筑类型

- 使用Canvas或SVG渲染游戏地图
- 玩家点击地图格子记录移动
- 自动触发格子效果：资源获取、事件触发等
- 显示玩家当前位置
- 显示建筑分布

#### 3.5.4 右侧面板
- 玩家数据展示：
  + 玩家ID、名称、颜色
  + 资源数量：wood、stone、rice

  + 已建造建筑列表（buildings）
  + 繁荣度（prosperity）

- Turn Queue循环：P1→P2→...→PN→Night

- 资源系统：管理wood、stone、rice等资源的增减
- 建筑建造：玩家在可建造格子上消耗资源建造建筑

## 4. 业务规则与逻辑

### 4.1 地图配置规则
- 地图必须包含至少1个格子
- 一个项目下可以创建多个地图
- 地图以方块网格形式排列，支持矩阵布局
- 每个格子的dayType和nightType可以不同
- replaceable为true时，replaceList不能为空

### 4.2 建筑建造规则
- 玩家必须在canBuild为true的格子上建造
- 建造消耗对应资源（wood、stone、rice）
- 建造成功后，建筑归属该玩家
- 建筑产生昼间效果（effectDay）和夜间效果（effectNight）

### 4.3 昼夜切换规则
- 所有玩家完成行动后，自动进入夜晚回合
- 夜晚回合执行：
  + 夜间收费：chargesAtNight为true的格子向停留玩家收费
  + 抢劫事件：触发stealResource动作
  + 战斗事件：触发diceBattle动作
- 夜晚回合结束后，进入下一轮昼间回合

### 4.4 事件触发规则
- 事件触发器类型：
  + enterTile：玩家进入格子时触发
  + nightStart：夜晚开始时触发
  + phaseChange：昼夜切换时触发
  + sameTile：多个玩家在同一格子时触发
- 事件条件（condition）满足时，执行动作列表（actions）
- 动作类型：
  + addResource：增加资源
  + stealResource：抢夺资源
  + taxCollect：收取税费
  + replaceTile：替换格子类型
  + diceBattle：骰子战斗

### 4.5 资源系统规则
- 资源类型：wood、stone、rice
- 资源获取：通过格子效果、事件动作、建筑效果获得
- 资源消耗：建造建筑、支付过路费、战斗失败
- 资源不能为负数

### 4.6 繁荣度规则
- 繁荣度（prosperity）通过建造建筑、完成事件等方式增加
- 繁荣度影响游戏胜负条件

### 4.7 日志记录规则
- 每次操作必须记录日志，包含：
  + 轮次（round）
  + 玩家（player）
  + 动作类型（action）
  + 详细信息（details）
- 日志用于回放和数据分析

### 4.8 保存与加载规则
- SaveFile JSON包含：
  + 地图配置（map）
  + 玩家状态（players）
  + 游戏状态（gameState）
  + 日志（logs）
  + 随机种子（seed）
- 加载SaveFile时，恢复所有状态和日志

## 5. 数据模型

### 5.1 Map（地图）
- id：地图唯一标识
- name：地图名称
- width：地图宽度（矩阵模式）
- height：地图高度（矩阵模式）
- cyclic：是否环形地图（布尔值）
- tiles：格子数组

### 5.2 Tile（格子）
- id：格子唯一标识
- name：格子名称
- dayType：昼间类型（Forest、Mine、Market、Empty等）
- nightType：夜间类型
- replaceable：可否被替换（布尔值）
- replaceList：可替换类型列表（数组）
- canStop：可否停留（布尔值）
- canBuild：可否建造（布尔值）
- hasEvent：是否有事件（布尔值）
- chargeAtNight：夜间收费（布尔值）

### 5.3 Building（建筑）
- type：建筑类型（Camp、Village、City等）
- level：建筑等级
- cost：建设成本对象{wood、stone、rice}
- effectDay：昼间效果
- effectNight：夜间效果
- canCollect：可否收取过路费（布尔值）

### 5.4 Event（事件）
- id：事件唯一标识
- trigger：触发器类型（enterTile、nightStart、phaseChange、sameTile等）
- condition：触发条件
- actions：动作列表（数组）

### 5.5 Player（玩家）
- id：玩家唯一标识
- name：玩家名称
- color：玩家颜色
- resources：资源对象{wood、stone、rice}
- position：当前位置
- buildings：已建造建筑列表（数组）
- prosperity：繁荣度

### 5.6 GameState（游戏状态）
- currentRound：当前轮次
- currentPlayer：当前玩家
- phase：当前阶段（Day/Night）
- turnQueue：回合队列（数组）
- players：玩家列表（数组）

### 5.7 Log（日志）
- round：轮次
- player：玩家
- action：动作类型
- details：详细信息

### 5.8 SaveFile（存档文件）
- map：地图配置
- players：玩家状态列表
- gameState：游戏状态
- logs：日志列表
- seed：随机种子

## 6. API设计

### 6.1 项目管理
- GET /api/projects：获取所有项目列表
- POST /api/projects：创建新项目

### 6.2 地图管理
- GET /api/projects/{id}/maps：获取项目下所有地图
- POST /api/projects/{id}/maps：创建新地图
- GET /api/maps/{mapId}：获取指定地图详情
- PUT /api/maps/{mapId}：更新地图配置
- DELETE /api/maps/{mapId}：删除地图
- PUT /api/maps/{mapId}/rename：重命名地图

### 6.3 游戏运行
- POST /api/games：启动游戏（传入地图ID和规则ID）
- POST /api/games/{gameId}/action：玩家行动（传入玩家ID和动作）
- GET /api/games/{gameId}/state：获取当前游戏状态
- POST /api/games/{gameId}/save：保存游戏状态为SaveFile
- GET /api/games/{gameId}/log：获取游戏日志

## 7. 异常与边界情况

| 场景 | 处理方式 |
|------|----------|
| 导入地图JSON格式错误 | 提示格式错误，拒绝导入 |
| 格子配置缺少必填字段 | 提示缺少字段，禁止保存 |
| 建造建筑时资源不足 | 提示资源不足，禁止建造 |
| 玩家移动到canStop为false的格子 | 提示不可停留，禁止移动 |
| 夜晚收费时玩家资源不足 | 扣除所有资源，记录负债状态 |
| 回放日志时日志数据损坏 | 提示日志损坏，停止回放 |
| 导出图表时无数据 | 提示无数据，禁止导出 |
| 调试模式下手动触发不存在的事件 | 提示事件不存在，忽略操作 |
| 多语言切换时部分文本未翻译 | 显示原文或默认语言文本 |
| 删除地图时该地图正在游戏中使用 | 提示地图正在使用，禁止删除 |
| 地图网格尺寸调整导致格子超出边界 | 自动移除超出边界的格子或提示用户确认 |

## 8. 验收标准

1. 用户创建新项目，进入地图编辑器，在地图列表区新建地图，在方块网格画布上点击添加至少5个格子，拖拽调整格子位置，选中格子配置dayType、nightType、canBuild等属性，导出地图JSON文件
2. 用户进入规则编辑器，定义至少1个建筑类型（如Camp），配置建设成本和效果，定义至少1个事件（如enterTile触发addResource），导出规则JSON文件
3. 用户进入游戏运行页，从地图列表选择已创建的地图，导入规则，启动游戏，添加2个玩家，玩家依次点击地图格子移动，触发资源获取和事件，在可建造格子上建造建筑，所有玩家完成后自动进入夜晚回合，执行夜间收费和抢劫事件，完成至少1轮完整的昼夜循环
4. 用户保存当前游戏状态为SaveFile JSON，进入日志回放页，加载SaveFile，使用回放控制器从头播放游戏过程，验证每一步的地图状态和玩家状态与实际游戏一致
5. 用户进入数据分析页，查看资源获得次数、格子访问频率、事件发生频率统计，生成柱状图，导出为PNG文件
